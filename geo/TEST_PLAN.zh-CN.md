# EAU 项目页的 AI 搜索曝光测试方案与结果

**版本：** 2026-10-15，实验方案 v1
**对象：** https://eau-meta-agent.github.io/
**目标问题：**“最近有什么 agent-environment co-evolution 的工作？”
**论文：** https://arxiv.org/abs/2610.16523
**候选改动：** [PR #3](https://github.com/eau-meta-agent/eau-meta-agent.github.io/pull/3)；当前尚未部署。

## 1. 要回答的问题

1. 用户用主题问题搜索时，EAU **论文**是否进入检索结果或答案？
2. **项目网页 URL** 是否进入检索结果？这与论文 URL 分开统计。
3. Agent 的最终答案是否提到 EAU，是否引用项目网页，并且引用支持其表述？
4. 改动后相对于改动前，以上结果是否在同一产品、同一问题、相同搜索设置下改善？

网页可抓取、页面可回答、搜索系统召回、最终引用是四个不同阶段。前一个阶段通过不能推断后一个阶段通过。结果必须保留原始来源链接或截图；没有来源面板的产品只统计可见的最终答案，检索排名记为未知。

## 2. 测试环境

每次记录日期与时区、产品、账号类型、模型版本、地区、语言、搜索模式、客户端版本，以及是否为全新会话。不要把网页搜索 API、某个 Agent App 和 Codex 内置搜索当作同一环境。

| 环境 | 设置与需要记录的证据 | 当前状态 |
| --- | --- | --- |
| ChatGPT Search | 在 ChatGPT 中开启/选择 Search；保存完整答案和 Sources 面板。其搜索可能改写问题并进行多轮搜索，引用不一定完整。参见 [OpenAI 官方说明](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt)。 | 未在 ChatGPT App 中实测 |
| Claude Web Search | 确认该会话使用网页搜索；保存答案及引用。参见 [Claude 官方说明](https://support.claude.com/en/articles/10684626-enable-and-use-web-search)。 | 未测 |
| Grok | 记录是否显示实时网页搜索，以及答案中的网页来源；区分 X 帖子与网页。参见 [X 官方说明](https://help.x.com/en/using-x/about-grok)。 | 未测 |
| 豆包 App | 记录 App/网页版本、是否联网、完整答案和来源面板。不要用火山引擎 API 的结果代替 App 结果。 | 已收到 1 次用户转贴的最终答案；缺少原始检索列表与来源面板 |
| Gemini | 保存答案及可用的 Sources/相关来源；没有来源时将引用字段记为未知。参见 [Google 官方说明](https://support.google.com/gemini/answer/14143489)。 | 未测 |
| Codex web search | 本实验环境的网页搜索结果，用作独立的检索基线；它不是 ChatGPT Search App 的实测。 | 已做 1 次基线 |

如使用火山引擎豆包搜索 API，另建环境：记录 Global/Custom 版本、检索参数和返回文档。其[官方产品文档](https://docs.volcengine.com/docs/Networkedsearch?lang=zh)说明两个版本覆盖范围不同；API 结果不能直接代表豆包 App。

## 3. 测试用例

**发现类用例不得在问题里给出项目域名，也不要先把页面粘贴给 Agent。** 用全新会话，明确启用网络搜索；不要在同一会话中连续提示“找 EAU”，以免后续轮次受到前文影响。

| ID | 原样输入的问题 | 意图 | 主要观察 |
| --- | --- | --- | --- |
| Q1 | 最近有什么 agent-environment co-evolution 的工作？ | 用户真实问题，中文广义发现 | 项目页/论文召回、EAU 提及、项目页引用 |
| Q2 | What are recent papers on agent-environment co-evolution for LLM agents? | 英文广义发现 | 与 Q1 的语言差异 |
| Q3 | Which recent methods co-evolve the training environment and agent policy, and how do they differ? | 方法比较 | EAU 与 SEAL、CoMAP、GenEnv 的关系是否准确 |
| Q4 | What work jointly adapts the environment, agent, and simulated user during multi-turn RL training? | 细分需求 | EAU 是否被识别为匹配工作 |
| C1 | EAU: Environment-Agent-User Co-evolution for Training User-Centric Agents | 标题控制组 | 论文与网页是否可按准确名称找到；不计入广义发现率 |
| C2 | https://eau-meta-agent.github.io/ | 直接 URL 诊断 | 页面是否能打开、摘要是否能读取；不计入自然召回率 |

Q1–Q4 是主要指标。C1 和 C2 用来诊断“站点根本不可读”与“读得到但主题问题没召回”的区别。不要因控制组成功而宣称自然曝光成功。

## 4. 执行与数据记录

1. **改动前：** 在 PR #3 合并之前，针对 Q1–Q4 在各产品各运行 3 次，每次新会话。存答案全文、来源 URL、截图/导出链接和模型版本。当前只有下表列出的一次 Codex web search 基线和一次用户转贴的豆包最终答案，不能补写其他历史结果。
2. **部署核验：** 合并后记录合并 SHA、GitHub Pages 部署时间；访问首页，确认新标题、SEAL/CoMAP/GenEnv 三个原论文链接直接出现在 HTML 中，并确认首页、`robots.txt`、`sitemap.xml` 返回 200。
3. **改动后：** 在部署完成后、24 小时、72 小时和 7 天分别重复 Q1–Q4；同一产品保持相同搜索设置与地区。若产品不提供原始搜索排名，`rank` 留空。
4. **录入：** 每个问题每次执行写入一行 `geo/observations.csv`，填写模型、搜索模式、地区和会话标识。`phase` 为 `before`/`after`；排名 `0` 表示检查的前 10 个结果没有该 URL，空值表示未知；提及、引用与答案准确性用 `1`/`0`，空值表示未知。运行 `python3 tools/visibility_report.py geo/observations.csv` 汇总。
5. **复核：** 另一名复核者打开被引用的 URL，核对作者、日期、方法和实验结论。错误归因、把论文站点与项目站点混淆、无依据的性能比较均判为不准确。

建议额外记录原始 JSON 或截图、是否用了引用/来源面板、是否发生多轮搜索、重定向后的最终 URL。完整来源 URL 比只保存域名更适合复核。

## 5. 指标与判定

| 指标 | 定义 | 不能推断什么 |
| --- | --- | --- |
| 本地代理分数 | `tools/geo_score.py` 的 20 项、100 分：抓取准备 20、论文身份 20、主题可回答性 40、导航 10、质量约束 10。 | 不代表搜索排名或引用概率。 |
| 项目页召回@10 | 前 10 个可见检索结果中有项目 URL 的次数 / 可判断的次数。 | 不代表最终答案引用。 |
| 论文召回@10 | 前 10 个结果中有 arXiv 论文 URL 的次数 / 可判断的次数。 | 不代表项目页曝光。 |
| EAU 提及率 | 最终答案明确提到 EAU 论文的次数 / 可判断的答案次数。 | 不代表任何来源被引用。 |
| 项目页引用率 | 最终回答明确引用项目 URL 的次数 / 有可判定引用面板的次数。 | 不代表引用内容准确。 |
| 论文引用率 | 最终回答引用 EAU arXiv URL 的次数 / 有可判定引用面板的次数。 | 不代表项目页被找到。 |
| 答案准确率 | 复核后，EAU 方法、相关工作差异与结果无实质错误的次数 / 可判定次数。 | 不代表来源覆盖充分。 |

同一个问题、同一个平台至少 3 次独立运行后再计算方向性变化；样本不足时只报告“x/y 次”，不报稳定的百分比提升。首要成功信号是 **Q1–Q4 中至少有一次项目 URL 被自然召回或引用，且引用内容准确**。若只增加 arXiv 提及而项目 URL 仍为 0，则论文可见性有进展，项目网页曝光目标尚未达成。

“后”当前仅指**未部署候选的本地评估**。PR #3 尚未合并，因此真实 Agent 搜索没有有效的改动后结果。

**当前结论：**用户转贴的豆包回答确实没有 EAU，也没有项目网页引用；它无法说明底层检索是否曾取回该页面。候选页面对 Q1 的相关工作介绍更完整，可抓取的 HTML 中直接包含三篇有出处的对照论文。现有证据尚不能证明任何 Agent 对项目网页的搜索召回或引用已经提升。对比必须在 PR 合并并部署后按相同环境继续收集。

## 7. 偏差与风险

- **索引延迟：** 合并后立即未出现，不能单独说明改动无效；同时不能用“还没收录”无限期解释失败。固定复测时间窗。
- **平台差异：** Agent 可能改写问题、选择不同搜索源，甚至不调用搜索。记下实际搜索状态，分别汇总平台和模式。
- **来源替代：** arXiv 与论文聚合站通常比新项目域名更早被发现。必须分别统计论文和项目 URL。
- **模型随机性：** 新会话重复运行、记录模型版本；不以一次回答下结论。
- **评分过拟合：** 100/100 是这份有限清单的上限。旧的 7/7 同样不能当作真实曝光；新增内容仍需靠外部搜索结果检验。
- **未部署候选：** 搜索平台目前无法检索到候选变更，不能把本地分数与现网结果组成因果前后对比。
